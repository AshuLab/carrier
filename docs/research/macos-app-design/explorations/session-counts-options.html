Session header: the counts line

Today it is one grey line under the name: 15 tool calls · 4 test runs, with +42 −8 in green and red and errors in red. It reads as a sentence, so nothing stands out and you have to read it to find the one number you care about (usually errors, or whether tests ran). Five ways to give it shape, same data, all in the header's two-line layout. Switch the case to see how each one copes with zero, many and error states.
What each one costs in the app. A, B and D are SwiftUI capsules in the header (an HStack of small views built from SessionCounts; countsRuns and its string tests go away or shrink to the labels). C adds a second row to the card, so the closed list gets taller (about 38 pt per session). E needs the proportions, which SessionCounts already has. The slice-lane headers use the same counts line today; whichever wins would apply there too, probably in its smallest form.
