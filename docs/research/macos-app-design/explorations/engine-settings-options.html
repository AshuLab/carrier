Engine settings: how the Behavior tab could look and work

The seven values of config.json the app edits. Everything below is clickable. Three questions: how the tab is laid out, how a number is entered, and what happens after Save, since the engine reads the file only when it starts. The bar at the top says what Carrier is doing, and the saving options below react to it.

1 · Layout

Same seven values, three ways to show them. A is what is built now.

2 · Entering a number

The built version is a plain text field that only takes the value on Enter or when you leave it. These two make the common choices one click and keep a typo from reaching the file. Shown on the two values where it matters most.

3 · Saving, and applying it

Edit a value with the steppers, then use the buttons. Switch the bar at the top to see what each option does when Carrier is stopped, running idle or running epics. Restarting interrupts running epics; they resume on the next start.
  • What I would pick: layout B (grouped, steppers with units, so each value reads as a sentence), numbers Presets + custom for the poll interval and hours (steppers for the rest), saving S3 (one button that says what it does, a confirmation only when epics would be interrupted).
  • Not in any option, by design: repos, profiles and agents (they stay in carrier init and the JSON), and root (read-only, it is where the socket lives).
  • Not knowable from the app: which values the running Carrier started with. The snapshot only tells the poll interval and the slots, so "applies after restart" is tracked by the app from the Save it did itself.
