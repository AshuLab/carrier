Repos: adding from GitHub, as it would look

The Repos tab as I would build it (the list with each repo's status, add and remove, S3 saving) and the sheet behind “Add repo…”: the repos your gh login can push to, grouped by owner, with search. Use the two bars: list changes how many repos are watched (few, many, one), sheet shows what the sheet does while loading, when it works, when it finds nothing and when it cannot list (Carrier stopped or GitHub failing). The ✕ on a repo asks before it takes it out.

Carrier is
  • Where the list comes from: the engine, with a new control request (say availableRepos, advertised in hello.capabilities so an older engine just shows the stopped message). The app never has a GitHub token (ADR 0005). It is what carrier init already does: gh api user/repos, only repos you can push to, archived and disabled left out.
  • Taking one out always asks: the ✕ opens a confirmation under the list that says what happens to its epics, or that it has none. Nothing is written until Save, and Revert undoes it.
  • It needs Carrier running (the engine does the read). Stopped: the sheet says so and offers only Cancel. There is no typing a name by hand: a repo that is not in the gh login's list is not one Carrier could use.
  • The repo is added to the draft only: it shows as “new”, and Save (and restart) writes it. The engine checks it on its first poll, so a repo the profile cannot reach shows up as a red row, as encaja does here.
  • The last repo cannot be removed: the config needs at least one. Pick “1 repo” above.
