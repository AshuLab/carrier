# New session

How a new session is planned in the draft and prepared by the chat host when the first message is sent; the conversation that follows is in [sessions](sessions.md#conversation).

Nothing is cloned, created or written until the first message is sent, and the draft is blank every time New session opens (the menu, ⌘N, or the + while it is open) and after a send.
Choosing a repository, a project or a folder only fills the plan.
Sending makes one `open` and the chat host prepares the session in the background, in this order and only the steps the plan needs: `clone` (or `fetch` when the repository is already in the projects folder) or `project`; `worktree` or `checkout`; `agent`; `message`.
The conversation lists the steps, each running, done or failed, until the agent answers.
A failed step stops there with its reason in words and the message kept; Try again repeats the steps that did not finish and reuses what was made.
Cancel, while it runs, stops the step, deletes the session with its worktree (a half clone goes too, a finished clone stays in the projects folder) and puts the plan and the text back in the draft.
A folder that already existed with uncommitted changes is never switched to the picked branch: the `checkout` step fails and says so, see [Troubleshooting](../troubleshooting.md#a-new-session-does-not-start).
A repository is added to the engine's `repos` only once the agent has answered.
The reasons are in [the spec](../specs/session-prepared-on-first-message.md) and [0018](../adr/0018-a-new-session-is-a-plan-and-the-host-prepares-it-when-the-first-message-is-sent.md); the details follow.

## The draft and the workspace

The + of the Sessions row, the New session button of the Sessions home and ⌘N (always on) select `Selection.newSession`: a draft in the centre (`Carrier/NewSessionView.swift`; the logic is `CarrierCore/NewSession.swift`) that shows a round mark (a placeholder for a logo), "What do you want to work on?", "Pick where it works, then write.", the sentence and a box with the agent chip; the toolbar takes the page's own colour, not the system's band.
Nothing exists until the first message is sent.
The workspace, a chip in the sentence, opens one popover that drills in (`CarrierCore/WorkspaceSources.swift` and `NewSessionModel`): the recent folders (`recentFolders`: the distinct base folders of the sessions the host lists, active and archived, most recent first, at most eight, with their paths), what is in the projects folder (the `<owner>/<repo>` and `local/<name>` folders on disk), Open local folder… (the system's folder panel), From a GitHub URL… (listed only when the host's hello has `repoBranches`, which comes with the plan for a repository), My GitHub repositories… (when it has `githubRepos` as well), New project… (only when it has `createProject`) and a footer with the projects folder's path and Change…, which opens the folder panel and sets `projectsFolder` in the chat's own `<folder>/chat/chat.json` (`applyingProjectsFolder`; the file is made when it is not there and its other keys are kept; the engine's config is not touched), absolute; the popover comes back showing the new path and what that folder holds, and what was in the old one stays where it is.
A folder inside the Carrier folder's `engine` or the chat's `state`, `logs` or `worktrees` (symlinks resolved, `projectsFolderRefusal`) is refused before anything is written, and a file that cannot be read or written is too, each said in red under the footer with the old folder still in place; the host reads the folder at each request, so the next clone or new project goes to the new one with no restart.

## A GitHub repository

The URL step takes `owner/repo` or a github.com address (`repoReference`; its button stays off until the text is one repository), says beforehand when the repository is already in the projects folder (the button reads "Use (updated when sent)", else "Use (cloned when sent)") and only fills the plan (`NewSessionModel.choose(repo:)`): nothing is cloned, `cloneRepo` is no longer called and nothing is written to the engine's config.
A repository that is not on the Mac (`toClone`) has its default branch and its branches read from GitHub with the person's login (the host's `repoBranches`, the first hundred, with a note when there are more), which fill the same branch picker as a folder's (as plain names, since a fresh clone follows the pick), shows no uncommitted-changes line and says where it will be cloned (`repoNote`); a worktree from a branch is offered like for any folder, with its name left empty, "generated when sent", and no ↻ or name check (the host makes it).
One that is already in the projects folder is read locally with `workspace`, as a folder is, and the note says it will be fetched.
Whatever the person chose, `send` puts the repository in the plan (`PlanWorkspace.repo`) and the host runs its `clone` step (git's progress under it in the conversation) or `fetch`, then the rest.
Under the field, "Let Carrier watch this repo" (on by default; off, with the reason, when `repoProblem` refuses the repository for the config's `repos`: already there, or a folder name another repo has) is a choice of the plan: once the session is sent, the model looks at the host's list every two seconds (`settleWatches`) and, when the session's preparation is over (the `message` step is done: no preparation left), adds `{ "name": "owner/repo" }` to the config's `repos`, the file read again just before the write and once only; a preparation that fails (it waits for Try again) or is cancelled adds nothing.
The session's conversation notes it (`watchNotes`; the repo is added to `repos` and the save asks the engine to reload); a config that cannot be read, is not a JSON object or is not writable is said there as a repository that could not be added to Carrier's list.
Deleting the session undoes neither the clone nor the watch.
Nothing is restarted.
My GitHub repositories asks the host for `githubRepos`, a page at a time (thirty repositories the person's `gh` login can read, newest push first, owner, collaborator and organisation member, archived and disabled left out, with no filter on push permission, unlike the Repos tab's Add repo picker, which keeps its own), and shows "Signed in to GitHub as <login>" (the login comes with page 1 only), a search over what is loaded, each repository with a lock when it is private, when it was last pushed and a "watched" tag when the config's `repos` already has it, a "Partial list" notice and a Load more button while the host says there is more (the paging is `AvailableReposList`, the Repos tab's, reused).
A first page that fails shows the host's reason in words with Try again; a later page that fails keeps what is loaded and offers Try again for that page.
Choosing a row fills the plan as the URL step does, and "Let Carrier watch the repo I choose", under the list and on by default, adds it to the config's `repos` the same way, after the message step; for a repository that is already watched it does nothing, and a row whose folder name another watched repo has says Carrier will not watch it and why (`repoProblem`).

## A new project

New project asks for a name only, shows the path it will make (`<projects folder>/local/<name>`), keeps its button off for a name the host would refuse (`projectNameProblem`, the host's own pattern, or a `local/<name>` already in the projects folder), and only fills the plan (`NewSessionModel.newProject`, with `choose(project:)`): nothing is made on the Mac and the draft says the path will be created when the message is sent; `send` puts the project in the plan (`PlanWorkspace.project`) and the host runs its `project` step (a folder with `git init -b main`).
The app no longer calls `createProject`.
It has no watch box, and having no commits (`WorkspaceInfo.offersWorktree` needs a branch) the sentence reads "in the folder (new project, no commits yet: no worktree)".

## When a tool is missing or signed out

With the host's `gh` `missing` or `signedOut` the sheet's From a GitHub URL and My repositories rows are off and say why (`workspaceSourceReason`, `NewSessionModel.sourceReason`; `show` refuses those steps too), while Recent, New project and Open a folder keep working; `ready`, `unknown` and a host that reports no health leave the sheet as it was (`WorkspaceSourcesTests`, `NewSessionTests`; the sheet's view has no automated test).
The agent chip lists the configured agents; one that is missing is disabled with "not installed" and one that is signed out with "signed out", while `ready` and `unknown` can be chosen.
The states are the chat host's `health` reply (`HostHealth`: `git`, `gh` and each agent as `ToolState` `ready`, `missing`, `signedOut` or `unknown`), which the app asks for (`HealthStore`, one for the app) when it opens once the host answers, when it becomes active again and on an explicit refresh (`HealthMoment`; opening takes the host's answer kept for thirty seconds, the other two ask for a fresh one), and only of a host whose hello lists `health` (`shouldAskHealth`); with an older host (or none yet) an agent whose binary was found is `ready` and one that was not is `missing`, as before (`agentChoices`).
The draft takes the first available provider and never preselects a blocked one (`pickAvailableAgent`, run again when the states change); when none is available the box says why (`noAgentReason`) and Send is off.
With `git` `missing` (`NewSessionModel.gitMissing`; `ready`, `unknown` or no health change nothing) the draft offers no New worktree and, where the folder's branch would be, the sentence says "in the folder (git is missing: no worktree, no branch. See Health in Settings)" (`workSentence(gitMissing:)`), with no uncommitted-files line; a worktree already chosen goes back to the current folder.
Each reason that Carrier can fix offers its fix (`CarrierCore/HealthFix.swift`): the fixed list `healthFix` is data keyed by what failed (a provider's harness and state, `gh`, `git`), with `claude auth login`, `codex login` and `gh auth login` for a signed-out `claude`, `codex` and `gh`, `xcode-select --install` for a missing `git`, `brew install ashulab/tap/carrier` for a missing `carrier` (`HealthTool.carrier`; the Health tab's `carrier` row), and, for a missing `claude`, `codex` or `gh`, no command but its installation page; the button (`Carrier/HealthFixButton.swift`) names the command and `fixInTerminal` opens Terminal on it with Continue in Terminal's one-use script (`openScript`, the same writer) and opener (`TerminalOpener`), each word quoted; what a probe, the host or the doctor returned (a name, a harness) is never part of a command, and a harness the list does not name has no fix.
The button shows in the draft under the box (a provider that is blocked, and `git` missing) and under the workspace sheet's rail (`gh`); coming back from Terminal re-checks the health (`HealthMoment.active`) and the reason goes when the state is `ready`.

## The folder, the branch and the worktree

Above the box the sentence reads "Work in Choose a workspace…" (orange), with the box dimmed and unable to send until one is chosen.
Once one is, the app asks the host what it is (`workspace`) and the sentence reads "Work in <workspace> on Current folder (<branch>)" ("detached HEAD" when there is no branch), with a line under it when the folder has uncommitted files (how many, and that a worktree keeps them out of the agent's way); a folder that is not a git repository (or is bare) reads "in the folder (not a git repository: no worktree)" and offers no worktree.
"Current folder" is a menu of two choices that switches to "New worktree carrier/<name> from <branch>", with a line under the box saying what it creates: the name is the host's `suggestName` with ↻ for another, the part after the fixed `carrier/` is editable and `checkName` asks about it 400 ms after the last keystroke (a taken or invalid name is red with the host's reason and cannot be sent), and the branch control opens a picker with a search, the local and the remote branches in two sections (the checked-out one marked, the default one tagged) and Fetch now (`fetch`), which says how long ago the remote branches were fetched.
The branch defaults to the one checked out in the folder, else the repository's default branch, else the person is asked.
Sending in a worktree puts `branch` (the one the worktree starts from) and `worktree: {name}` in the plan; a refusal is said in the draft.

## Sending and the preparation

The draft is blank every time it opens (`NewSessionModel.blank`, run by `load` and, for the menu or the + while the draft is already open, by the window's `newSessionOpened` count): no workspace, no worktree choice or name, no text.
The workspace chip has a ✕ once a workspace is chosen (`clearWorkspace`: the workspace and its branch, worktree choice and name go, the text stays), and after a send the draft is blank again, so the next send carries nothing of the last one; choosing a repository, a project or a folder only fills the plan.
Opening the draft (`NewSessionModel.load`) starts the chat host when it is not running (`ChatHostStarter.ensureRunning`) and asks it again for the agents and the recent folders; sending (`NewSessionModel.send`) starts it too when it went away (`ChatHostStarter.ensureRunning`), makes one `open` that carries the plan (`SessionPlan`: the folder as a workspace, the agent, the options chosen, the first message, and the branch and worktree name for a worktree) and nothing else, and selects the session, which the host answers at once in the `preparing` state and shows in the sidebar as working.
The app sends a plan only when the host's hello lists `plan`; against one that does not the draft says the host is older and to restart it (`NewSessionModel.hostOlder`, checked again at the send) and sends nothing, and the old `open` of a folder and a worktree is no longer used by the app.
A refusal of `open` is said in the draft and the text stays.
The conversation of that session shows the steps as a list at its top (`preparationSteps` in `CarrierCore/PreparationSteps.swift`, a pure function from the `step` events and the `preparation` of the `events` reply, with the `progress` line on the running step): each step running, done or failed with a line in words and the reason under a failed one, until the agent answers; the first message shows as the person's message until the host records it (`ConversationModel.show(firstMessage:)`), so a failed step does not lose the text.
A first message that names a command of the agent is carried as typed.
A failed preparation shows Try again under the list (`ConversationModel.retryPreparation`, the host's `retryPreparation`: it repeats the steps that did not finish and reuses the worktree and the checkout already made), and one that is preparing shows Cancel (`cancelPreparation`: the host stops the running step and deletes the session with its worktree and answers the plan, which the app hands to the draft with `NewSessionModel.restore`; the draft that opens next, `load`, puts back the folder, the branch or worktree and its name, the agent, its options and the text); a refusal of either is said in words under the list.
Both are for a host whose hello lists `plan`.
The model, the sentence and the lists are tested with a fake `ChatHost` (`NewSessionTests`); `--smoke-window` prints what the draft offers, what the popover lists (`new session picker:`), a repository through the fixture host whose branches are listed and one that is refused, and a new project that works and one that is refused beforehand.
