# Spike: switching and delegating between agents

Throwaway scripts that settle the open questions of [switch-and-delegate-between-agents](../../specs/switch-and-delegate-between-agents.md), written on 2026-11-16 against Claude Code 2.1.325, the SDK pinned at 0.3.311 and Codex 0.167.2, the versions installed here.
The scripts are disposable and the findings are what stays: each part writes a `results-<part>.md` in this folder, and the summary goes to [switch-and-delegate-spike](../switch-and-delegate-spike.md).

## Rules for every part

- Create files only in this folder.
  Do not edit anything under `src/`, `docs/` outside this folder, `package.json`, the lockfile or any config; copy the adapter code into this folder when an experiment needs a changed one.
- Run TypeScript with `node file.ts` (Node 26 strips types; relative imports end in `.ts`), with pnpm only and never npm or yarn.
  Dependencies are installed already.
- Use the real adapters the way the integration tests do: `src/chat/claude.integration.test.ts` and `src/chat/codex.integration.test.ts` show how to open a conversation with the user's own binary and login, and how to start the chat MCP (`startMcpServer`, `McpSessionRegistry`, `defineTool` in `src/chat/mcp.ts`, `src/chat/mcp/capabilities.ts`).
- Real agents run in a temporary folder made with `mkdtemp` under `/tmp` (short path, `realpath` it), with the cheapest model each harness lists, tiny prompts, and at most the turn budget of the part.
  Stop and report at the first usage limit or rate limit instead of retrying.
- Never touch `~/.carrier`, never read or print anything of `~/.claude` or `~/.codex` that is a login, a token or a secret, and never print the environment.
- Never `pkill`, `pgrep | kill` or kill a process found by name: kill only a PID that the script captured when it started it, and close every conversation at the end.
  The installed Carrier may be running on this machine.
- An approval that a probe does not need is denied, so a probe never changes anything outside its temporary folder.
  A file written outside the folder goes to a unique new folder under `/tmp` that the script removes at the end.
- Report what was observed apart from what was inferred, and mark anything not checked as UNVERIFIED.
  Do not guess a result that a run did not give.

## Parts and what each must answer

- **A, Claude**: which permission modes (`default`, `acceptEdits`, `plan`, `auto`, `dontAsk`) send one MCP tool to the person's approval while another stays pre-approved, what each mode lets an agent do without asking, and what opening with a model does.
- **B, Codex**: the same for Codex's approval policies and sandboxes, what its elicitation carries, and whether `thread/start.config` merges with the person's own configuration.
- **C, handoff**: whether a handoff of 16,000 bytes plus a `history` tool keeps a conversation going between the two harnesses, and where it can sit when the first message invokes a command.
- **D, limits**: which signal of a usage limit the chat's adapters can rely on, and where the reset time comes from, without using up any quota.

## What is kept

Only the recordings that the epic's tickets replay are kept in `codex/logs/`: the real usage limit (`b4.jsonl`), the elicitations of one tool that asks and of the allowance for the session (`b1-V1-on-request-accept.jsonl`, `b1-V5-on-request-accept.jsonl`, `b6-V3-persist-act-then-read.jsonl`) and the summaries.
The other logs of the Codex part, about 4 MB, are regenerated by its scripts, and a log that holds an account id is not kept.
The home folder in what is kept is written `/Users/<user>`.
The Claude scripts take the path of the binary from `CARRIER_IT_CLAUDE_COMMAND` and fall back to `claude` on the path.
