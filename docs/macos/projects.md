# Projects

A project is an entry of `projects.json` identified by its folder: the Projects page of Settings, and the parts of a new session that choose, create or add one.

## Projects page

Settings has a Projects page (`Carrier/Features/Projects/ProjectsTab.swift`, `SettingsPage.projects`, in the Workspace group between Sessions and Sidebar, "The folders you work in"), the list of the projects a person works on ([the spec](../specs/projects.md), [0041](../adr/projects/0041-a-project-is-an-entry-of-projects-json-identified-by-its-folder.md)).
It is a full-width list, found in the search by its name.
With no projects it shows an empty state with Add project; with some it shows a search field (matching name, remote and tag), a Group choice (None, Tag or Carrier), a wrapping row of filter chips (All, each tag in use, Watched: only the ones Carrier watches, `ProjectFilter.watched`, Local only and Hidden: only the hidden ones, `ProjectFilter.hidden`), an Add project button and the list with Project, Tags, Last active, Disk and Carrier columns; Carrier says Watching or Not watched (`ProjectRow.carrierText`, `projectsWithWatched`: the project's `owner/name` is in the engine config's repos, compared without regard to case, read when the page opens).
Rows are ordered pinned first and then by name, or by when a session last worked in the project when the Last active title is clicked (most recent first, a second click reverses it, and a project no session worked in is last either way; clicking Project goes back to A to Z), or by what it takes on disk when the Disk title is clicked (biggest first, a second click reverses it, and a project never measured is last either way), the sorted title showing a small chevron for its direction (`ProjectOrder`, `ProjectSortKey`, `projectList(order:)`); the list can also be grouped under each project's first tag and "untagged" when grouped by Tag, or under Watching and then Not watched when grouped by Carrier (`ProjectGrouping`; a group with no rows is left out), with "Nothing matches" when the filters leave nothing; each row shows the project's tile (its chosen image, its chosen colour and mark, or initials on a colour made from its name when none is chosen), its name (the folder's name when none is set), the GitHub `owner/name` of its `origin` or else its path, its tags as chips, how long ago a session last worked in it or a dash when none did (`projectsWithLastActive`: the latest `updatedAt` of the sessions whose base folder is the project's path, compared with `~` expanded, symlinks resolved and no trailing slash, derived at each draw and never written to `projects.json`), what it takes on disk (`formatDiskSize`: "6.4 GB", "75 MB" or "310 KB"; the host's last figure for its folder and its worktrees together, `projectsWithDisk`) or a dash when the host has not measured it yet, a pin mark when pinned, and a chevron.
When the card is too narrow for the Project column to keep a readable width, the Tags column goes first and then the Carrier one (`ProjectColumns`), so at the window's first size (940 wide, the sidebar at 240) every column shows, and at its smallest (760) Tags is dropped; Carrier stays a Group choice and a filter when its column is gone.
The host measures in the background and keeps each figure with when it was taken (`projectDisk`, behind the `projects` capability): when the page opens the list shows what the host has and asks again for the projects never measured or measured a day ago or more, which the host measures one at a time, and it reads the host again each second only for the folders being measured, so a figure shows when it lands (`ProjectsModel.refreshDisk`, `follow`).
A host that does not answer leaves the dashes.

A hidden project's row is drawn dimmed and says "Hidden" with an eye-off mark under its name (a folder that is not found says that instead).
The Projects page ends with a line saying where new clones go ("New clones go to …") and a Change… button that writes `projectsFolder` in `chat.json` using the same rule as the session sheet, refusing folders inside Carrier's own folders.
The remote is read from the repository each time (`originRepo(ofFolder:)` in `CarrierCore/Projects/ProjectNaming.swift`, the `origin` of its `.git/config`) and is never stored; an `origin` that is not GitHub's, or no repository, shows the path.
Add project opens a sheet (`AddProjectSheet.swift`, driven by `projectSheetState` in `CarrierCore/Projects/ProjectSheetState.swift` in its Settings mode) with one search and path field, Suggested recent folders that are not yet projects, drag and drop from Finder, keyboard navigation (Return, up and down arrows, Escape, and ⌘O), and Open a folder… in its footer.
Typing filters the suggested folders, and a path starting with `~` or `/` offers Add folder (or Already a project · Open when that folder is already in `projects.json`); adding writes an entry with `origin` `added` and the folder's name (`ProjectsFile.add`: the file is read again just before, and every other entry and key is kept), closes the sheet, and opens the new project's page.
A folder inside Carrier's own folders (`engine`, `chat/state`, `chat/logs`, `chat/worktrees`, `chat/pending`, `chat/sessions`, with symlinks resolved), a file, a folder that cannot be read, or a worktree linked to another project is refused with the reason in orange (`projectFolderRefusal` in `CarrierCore/Projects/WorkspaceSources.swift`, `ProblemLine`), and writes nothing.
A folder whose worktree directory (`<owner>/<repo>`, or `local/<folder name>` without a GitHub origin, compared without regard to case) is the one of another project is refused the same way, with the other project named, whether it comes from the sheet, a drop or Locate… (`worktreeClashRefusal` in `CarrierCore/Projects/WorkspaceSources.swift`, `ProjectsModel.addRefusal`).
The host's `checkWorktreeClash` in `src/chat/names.ts` is the same rule for what it registers (a clone started from Settings that would clash is not registered and fails with the same words, the clone left as it is), and both tests read `macos/Tests/Fixtures/worktree-clash.json`.
A folder that already is a project, written any way (`~`, a trailing slash, a symlink), writes nothing and opens that project's page.
The same field takes a GitHub address or `owner/name` (`repoReference`) and searches the person's repositories (the host's `githubRepos`, five pages of thirty at most, with each one's description and last push and a Private chip): a pasted repository is the result "Clone owner/name" with "Clones into <projects folder>/<owner>/<name>" and Choose…, which changes the parent folder for that clone only and leaves `projectsFolder` as it is; a listed one that already is a project (its `origin`) shows Already a project · Open instead of Clone.
A pasted repository that is not among the person's own is looked up with `repoBranches` once typing pauses, and one the login cannot see shows "Your GitHub login can't see this repository. Check the name, or sign in with another account." in orange with Clone off (`repoNotVisibleLine`, told from a failure of `gh` by the host's words, `isRepoNotVisible`); a missing or signed-out `gh` shows the host's own wording for it.
A host whose hello lacks `projects` shows the clone results with Clone off and the words that the host is older and to restart it (`projectsNeedNewerHost`).
Clone asks the host for `cloneProject` and closes the sheet: the host clones in the background, the list shows the project as Cloning with git's latest progress line and without a chevron (it cannot be opened), and when git ends the host writes the entry with origin `cloned` (`added` for a folder that was already there and only fetched) and the row becomes a normal project; a failure stays in its row in orange with the host's reason and a Dismiss button (`dismissClone`).
`ProjectsModel` asks the host for its clones when the page opens and, while one is running, once a second (`projectClones`); a second clone of the same repository while one runs is the same clone.
Add project never makes Carrier watch what it clones; watching is the switch on the project's page.
The sheet is shared with New session, which opens it in its own mode (`ProjectSheetMode.newSession`, [New session](new-session.md#the-draft-and-the-workspace)): there a choice only fills the plan, the projects that are not hidden come first, a repository says it is cloned when the first message is sent and offers "Let Carrier watch this repo", and the sheet has no Choose… for a clone's parent.
The sheet's footer has New project…, which swaps the sheet for a form (`NewProjectForm` in `CarrierCore/Projects/ProjectSheet.swift`): a Name and a "Create in" line showing `<projects folder>/local/<name>` with Choose… for this one project only (`projectsFolder` stays as it is, and a folder inside Carrier's own is refused as it is for a clone).
A name that is not letters, digits, `_`, dots and dashes (starting with a letter, a digit or `_`, at most a hundred) is refused with the reason in orange (`projectNameProblem`, the host's own pattern), and so is a name whose folder is already there or that already is a project (`ProjectsModel.isTaken`); Create stays off while either is shown.
Create asks the host for `newProject`: it makes the folder, runs `git init -b main` in it and writes the entry with origin `created`, the sheet closes and the new project's page opens; the host refuses again what the app refused (a folder that is there, a name it does not take, a parent inside Carrier's own folders, a `projects.json` that does not match its schema) and then writes nothing.
Back returns to the chooser with what it had read.
Choosing a row opens the project as a screen of its own, a place of the window's history (‹ goes back to the list) in a centred column, with the project's name and its remote or path in the toolbar, and a Pin button in the page's header.
Its Identity group holds Name (emptied, it goes back to the folder's name, and a blank name is never written), Icon (Change… opens a popover of eight colours, eight existing `AppIcon` marks stored by the icon's name, and Choose image… to pick an image copied at most 256 points into `app/project-icons` as a PNG, cleared and deleted when a colour or mark is chosen afterwards, with a missing copy falling back to colour and mark) and Tags (Return adds a tag, trimmed, lower case and without repeats, and a cross removes it), each change written at once while keeping every other key.
Under Identity, a New sessions here group has the "Show when starting a session" switch (`ProjectsModel.setHidden`, which writes `hidden` and, when the switch is on again, takes the key out and changes nothing else); off, it says the project does not appear in the new session picker and that nothing is deleted.
The same group has Starts with (the panel of Settings > Sessions, `ModelPickerButton`, whose first row is Same as everywhere with what Settings > Sessions names now), Work in (Default, Base folder, New worktree) and Base branch (Default branch, then the project's branches, remote ones by their bare name).
Starts with writes `defaults.agent`, `model`, `effort` and `access` together through `ProjectsModel.setStart` (choosing another provider drops its reasoning and access, and Same as everywhere takes all four out); the others write `defaults.workIn` (`baseFolder` or `worktree`) and `defaults.baseBranch` through `ProjectsModel.setDefault`; a value left on the default takes its key out (`applyingProjectDefaultsEdit`) and `defaults` goes with the last key, so nothing is written for it.
Work in and Base branch are shown only when the host lists branches for the folder, so a folder that is not a git repository has just Agent.
A new session in the project opens with these, over Settings > Sessions ([new session](#a-projects-defaults)).
Hiding takes the project out of the sheet New session opens (among the projects and among the suggested folders) and nowhere else: it stays in this list, its sessions stay in the sidebar, and Settings' Add project still recognises it as Already a project.
Under it, a Worktrees and disk group (only for a project whose folder is there) lists the main clone with its branch ("Main clone" under it) and then each worktree Carrier made for sessions of the project, in the order git lists them.
A worktree's row says its branch, then the session that made it ("No session" when that session is gone, "Untitled session" when it has no title yet) and its age as the Time format says it, and ends in two chips, an activity and an integration, then the number of its pull request.
The activity is Session open or Uncommitted changes, shown only when one applies (Session open first when both do), and it is what disables Remove and what Clean up skips.
The integration is always there, exactly one, the first that applies: Merged (the session's saved pull request is merged), In main (the worktree's HEAD is already in the remote default branch, which is a git fact: its work was merged without a squash, or it never had commits of its own), Not pushed (commits no other branch holds), PR open (open or draft), PR closed, else Pushed (its commits are held by another branch, in practice the remote's, with no pull request).
A squash merge is never in main, so for it only the saved pull request says Merged.
The remote default branch is what `refs/remotes/origin/HEAD` points at: with no `origin/HEAD` the host does not guess `main` and no worktree says In main, and the host does not fetch, so a stale `origin/main` can only say In main too seldom.
The pull request is the one saved on the session, whatever the integration says, and its number (`PR #1495`, the piece of a session's pull request) opens its page on GitHub; a worktree with no session or no pull request saved has none.
A detached HEAD has no branch to hold its commits, so those that no branch holds count as Not pushed.
The page refreshes the pull request state when it opens: the host asks GitHub, in one request, for every session of the listed worktrees whose saved pull request is open or draft, archived sessions included and whatever the age of the saved state, before it says the chips (`projectWorktrees` and `cleanProjectWorktrees`, with or without `run`), so a worktree whose pull request merged says Merged when the page opens.
When GitHub cannot answer, the saved state shows, the list still opens and the host logs the failure; a project with no open pull request asks nothing, and Remove does not ask.
A worktree with a detached HEAD says "Detached HEAD" for its branch.
The host answers it when the page opens (`projectWorktrees`, behind the `projects` and `worktreeIntegration` capabilities): only worktrees git lists for the project's folder that lie under Carrier's worktrees folder and are still on disk, so one git still lists whose folder is gone is not shown.
A host without them says what a host that predates `projects` says (restart it), and no chip is drawn; a folder git cannot read shows the host's reason in orange in the group.
The group starts with Total, which says what the project takes on disk (the main clone and the worktrees together, with a small spinner and "Measuring now" while the host measures it, else "Measured 3h ago", or "Not measured yet"), and a bar under it with one segment for each folder, the main clone first, as wide as its share of the total (`DiskBar`, `diskShares`).
Each row ends with a dot in its segment's colour and its size, a dash for a folder the host has not measured (a worktree made since).
Opening the page asks the host for a fresh figure of this project (`projectDisk` with `refresh: now`) and shows the last known one meanwhile, so a project that was measured shows its sizes at once and they change when the new figure lands.
A project whose folder is gone has no Worktrees and disk group, so no figure, and a dash in the list.
A project whose folder is there but is not a git repository (`isGitRepository`: it has no `.git`) is a project like any other in the list, which searches, filters and sorts it, and a session started in it works in its folder.
Its page has no Worktrees and disk group, no base branch row and no Carrier switch, and says why in one line under New sessions here ("Not a git repository, so it has no worktrees, base branch or Carrier switch."); its Work in choice offers only the base folder.
What a page has is a pure function of the row (`ProjectPage`, `ProjectsListTests`).
Each worktree's row has a Remove button, the trash icon alone with no word, before its size (the main clone has none; its tooltip is "Remove this worktree's folder" and a screen reader reads "Remove the worktree" with the branch) that asks the host for `removeProjectWorktree`: only the worktree's folder goes, with what git ignores in it, and its branch, its commits and its session stay, so the session's next message brings the folder back on its branch.
The button is disabled, with "Its session is open" as its tooltip, while the worktree's session is open; with uncommitted changes it is pressed and the host refuses, and its words ("It has uncommitted changes") replace the row's second line in orange until the next try.
A project that has a finished worktree also has a Finished worktrees row, "Merged or already in main, nothing blocks them: 3 worktrees, 1.2 GB", with a Clean up button that asks "Clean up 3 worktrees, 1.2 GB?" and says the folders go and the branches and sessions stay.
What it takes is every worktree that has a session, whose integration is Merged or In main, and that has no activity (`cleanProjectWorktrees`, which the page asks without `run` for the figures and with it to act); one that has uncommitted changes or an open session is skipped, and a "Last clean up" row says what went and, for each one skipped, its folder's name and the reason, each on its own line and none cut.
A worktree with no session is never in Clean up, even when its HEAD is in main, because with no session nothing brings its folder back; it can be removed by hand.
A session made a moment ago and idle that says In main loses its folder here and gets it back with its next message.
After a removal or a clean-up the page asks for a fresh figure of the project, so the total and the bar follow the folders that went.
The size of each folder is what git does not count: the host walks the folder when Clean up asks, so the page asks only when a worktree with a session is Merged or In main, and shows no row when the host says none can be taken.
After Worktrees and disk, a Carrier group has one switch, "Let Carrier watch this project" (`ProjectWatchRow`, `projectWatchRow`, `watchChange` in `CarrierCore/Projects/ProjectWatch.swift`, which makes the list `setWatchedRepos` is asked for), on when the project's `owner/name` is in the `repos` of `engine.json` as the file is when the page opens.
Turning it on asks the engine for the list with the repository added (`setWatchedRepos` through `saveEngineConfig`, or `carrier config` when the engine does not list `config`: Node reads the file again just before, keeps every other key and every other repo's fields, and makes the engine run on it, which `ReloadStatus` keeps); turning it off asks "Stop watching owner/name?" with the Watching page's words about the project's epics (`removalText`) and then removes only that entry.
The row's second line is the Watching page's note (`settingsNote`: Carrier applies it to the next epic, or reads it when it starts when Carrier is stopped); a refusal of the Watching page's rules (a watched repository whose folder name is the same, `repoProblem`), an engine config that does not hold (`reposProblem`), a file that cannot be read or written, and an engine that kept its settings or did not answer take the line's place in orange, and nothing is sent for the first.
A project with no GitHub origin has the switch off and disabled, saying why; removing a project never changes it, and the Watching page is unchanged.
The screen has an Actions row showing how many actions are set ("None" or "N actions") and a chevron, which opens an Actions screen of its own with the project's name under Actions in the toolbar.
The Actions screen has two groups, New worktree and After clone, each listing its actions in order and ending in Add action, where each action has a name, an on switch, a delete button, a monospaced command field and an "If it fails" choice of Warn and continue or Stop the session.
Each valid edit writes at once to the project's `actions` in `projects.json` (omitting `on` when on and `onFail` when Warn and continue), while a blank name or command is not written and is shown as a problem.
The screen also shows the folder with Reveal in Finder (off when the folder is not there) and the remote with Open on GitHub, only when there is one.
Its last row is Remove…, which asks "Remove <name> from Carrier?" and says that the folder, the worktrees and the sessions stay where they are and that watching is not changed (`projectRemovalWords`).
A project whose origin is `cloned` or `created` (a folder Carrier made) is asked in a dialog with Remove from Carrier, Also delete from disk and Cancel, and the second says it moves the folder and N worktrees (their size, when measured) to the Trash and that the space is freed when the Trash is emptied (`deleteFromDiskWords`); a project with origin `added` gets only the question above ([0040](../adr/projects/0040-deleting-a-project-from-disk-is-only-for-what-carrier-made-and-goes-to-the-trash.md)).
Also delete from disk asks the host for the project's worktrees and sessions again at that moment (`ProjectsModel.deletionCheck`, `projectDeletionCheck`) and refuses, naming each session, while one of the project is working, waiting or open, and with a host that cannot say whether the folder has unsaved work; when the folder or a worktree has uncommitted changes or commits no remote holds it lists them and goes on only after Move to the Trash anyway.
The folder and its worktrees (only those under the chat's `worktrees/` folder) go to the Trash with `FileManager.trashItem`, never removed outright, and the entry goes only when all moved; when one cannot (another volume, a permission) the reason is told, what had moved is put back and nothing is removed (`ProjectsModel.deleteFromDisk`, `moveProjectToTrash`).
The sessions of the project stay; an idle one whose folder (its worktree's base folder) is gone shows "This session's folder was deleted" above the box and a send is refused with that reason (`ConversationModel.folderGone`).
Confirming takes the entry out of `projects.json` and deletes the project's image copy in `app/project-icons` unless another project names it (`ProjectsModel.remove`, the `removeProject` request: Carrier's own code reads the file again just before and keeps every other entry and key), then goes back to the list.
It never writes `engine.json`, so a watched project stays watched, and it touches nothing on disk but those two; the sessions keep their folder and group as a plain folder would.
A project whose folder is gone (`ProjectRow.status`, `notFound`, from `projectFolderExists`, read each time with the list) shows "Folder not found" in orange in its list row in place of its remote or path, with a dash under Disk, and its screen opens with a Folder not found row that has Locate….
Locate… opens the system's folder panel; the chosen folder goes through the same check as Add project (`projectFolderRefusal`: a file, a folder that cannot be read, one inside Carrier's own folders or a worktree of another project is refused with the reason) and a folder that is another project's is refused too, and then `ProjectsModel.locate` replaces only the entry's `path` (`applyingProjectLocation`: name, tags, icon, defaults and actions stay, and so does every key the app does not know).
The screen then opens that project at its new path as any other; the sessions that remember the old path are not rewritten and stay where they were.
The list and each project's screen follow the file while the page is open: `ProjectsModel.follow` reads it again every second, so what the chat host or an editor writes shows without reopening the page.
A file that does not match its schema, or cannot be read, shows each problem on the page with its field named (`projects.json: projects.0.name must not be blank`) in place of the list, and the page writes nothing while it is wrong.
A project's name and icon show wherever the project does, not only on its page.
A sidebar group, the rows of a session (in the sidebar, the Sessions home and the archive) and its hover card take the title and tile of the project whose folder is the session's base folder, and the rows and card of an epic take the tile of the project whose `origin` is the epic's repository (`owner/name`, case aside).
Two projects with one name keep the parent folder added to the title of their groups (`dev/Site`, `me/Site`), as two folders do.
A folder that is not a project, and a project with nothing set, draw as they always did: the folder's name and initials on a colour made from it, and an epic of a repository no project has as its `origin` draws as before.
The Watching page is unchanged.
`--fixture` has two clones in the list at the start (one at 62% and one failed, from `chat-project-clones.json`), and a repository of the listing starts cloning and stays at its progress line; it has eight projects: one pinned with tags, a colour and a mark, two actions and a GitHub origin, one whose name and remote are very long, a folder with a colour that is not a repository, one that is not there with a missing image copy that falls back to colour and mark, one with a copied icon image whose origin is `acme/web` (the fixture's epic repository), and the folders of the fixture's sessions: one with a name, colour and mark, one with the same image and one with nothing set.

## A new project

New project… in the sheet's footer swaps the sheet for the form of Settings (`NewProjectForm`) in its own mode: a name only, "Will be created in" with the path it will make (`<projects folder>/local/<name>`, no Choose…) and the button "Use this project"; it keeps its button off for a name the host would refuse (`projectNameProblem`, the host's own pattern, or a `local/<name>` already in the projects folder), and only fills the plan (`NewSessionModel.newProject`, with `choose(newProject:)`): nothing is made on the Mac and the draft says the path will be created when the message is sent; `send` puts the project in the plan (`PlanWorkspace.newProject`, whose `kind` stays `project` on the wire so an older host still reads it) and the host runs its `project` step (a folder with `git init -b main`).
The app no longer calls `createProject`.
It has no watch box, and having no commits (`WorkspaceInfo.offersWorktree` needs a branch) the sentence reads "in the folder (new project, no commits yet: no worktree)".

## Add as project

A folder chosen with Open a folder (or dropped, or a recent one) stays a plain workspace.
Under the sentence the draft then shows a small Secondary button, Add as project (`NewSessionModel.offersAddAsProject`, drawn in `NewSessionView`), that writes an entry of origin `added` with the same writer the Projects page uses (`ProjectsModel.add`, which refuses a folder that cannot be a project and says why next to the button, `addProjectProblem`).
The button is gone once the folder is a project, and a repository, a new project and a folder the host could not read never show it.
A repository the host clones, a repository only fetched and a new project are registered by the host when the preparation succeeds, with no button ([the chat host](../../src/chat/AGENTS.md)).

## A project's defaults

A project can set the agent, where to work and the base branch a new session there starts with ([Settings' Projects page](#projects-page)).
Choosing the project (`choose(folder:)`, `choose(repo:)`; the match is `isSameFolder` against `ProjectsModel.rows`) fills the draft from its `defaults` (`NewSessionModel.projectDefaults`) once the host has said what the folder is: the agent, when it can work, else the draft keeps the one it had, with the model, reasoning and access the project names for it (over Settings > Sessions', which the project's access is merged over); the base branch, when the folder has it, as the branch the draft starts from; and the worktree switch, which the project's Work in wins over Settings > Sessions' "Work in", which stands when the project sets none.
The draft shows each of them as its own choice (the agent chip, the worktree choice and the branch picker), so the person changes them there, and the next folder starts over from its own project's values.

The words of the Projects page, the sheet it shares with New session and the Cleanup group that sits in its folder are copy keys (`projects*` and `cleanupGroup*` in `design/copy/`), and `ProjectsSpanishTests` and `WorktreeChoiceSpanishTests` render each function that builds a sentence in Spanish; the model that says a failure (`ProjectsModel`) takes the `bundle` and `locale` it says it in, like the pure functions.
