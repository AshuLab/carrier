Epic view aligned with the chat — round 1

The epic's centre (pipeline, header, tabs, Agent output) was drawn before the chat existed. The chat has since settled how the same things look: quiet grouped tool cards, plain markdown for the agent, one rounded card for a file's diff, state by glyph. Three ways to bring the epic view in line, with the data of epic #729 from the screenshots. Switch the state to see the builder's log, the review round and the folded list.

What is out of line today
Two languages for the same thingThe chat groups tools in a glass card ("Ran 6 commands"); here a call is a bare line, a slice is a card with 4 chips, a created branch is a raw "created 736 (main)" line and the reviewers say "Used 98 tools".
The agent's words sit in a grey boxIn the chat the agent writes on the window and the user is the one in a bubble. Here every message is a full-width grey block, so the log reads as a stack of boxes.
Header with no hierarchyA full-width pipeline with 1,000 px of empty line, a 30 px glyph, a bold title, three chips and a tab row: five things of equal weight before any content.
Session cards: heavy shell, no verdictCounts in four chips, then you open to find the outcome. The review's verdict ("Ready — 0 blockers, 4 suggestions") is inside a markdown wall; the stop reason is a red line under chips.

A · Same vocabulary as the chat, sessions as quiet sections

Least change. Drop the session shell: a sticky one-line header per session (who, plain-text counts, time), then the chat's rows under a thread rule: plain markdown, a glass card for tools, the chat's file card, one card for the slices. The pipeline keeps its place but stops stretching.
