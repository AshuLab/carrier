An agent message that is a JSON object

What it is. Some agents end a session with a JSON object as their message (here a ship slice report: slice, outcome, branch, pr, definitionOfDone and a note). The app shows it as the raw code block: every key and brace is read, the one sentence worth reading (the note) is buried in a string, and "did it all pass?" takes counting six true. Four ways to render it; the first is today. Switch the case at the top to see a failing item and a shape the app has never seen (the last must still look decent, since the keys are the agent's choice).
What the data allows. A known shape is a convenience, not a contract: the keys are whatever the agent's skill prints. So the renderer needs two levels. Known keys (outcome, pr, branch, note, a map of booleans) get the nice treatment; anything else falls back to a labelled key/value list (option B, the "Unknown shape" case). A string that is a URL becomes a link, a map of booleans becomes a checklist, and a long string becomes prose. Invalid JSON stays the code block it is today.
