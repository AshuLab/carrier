# Usage fetching, history scanning, and UI patterns across CodexBar, T3 Code, and Paradev

> Research of 2026-11-12 to resolve the open questions in the `usage-and-limits` brief ([usage-and-limits.md](../specs/usage-and-limits.md)). Primary sources: `steipete/CodexBar` docs and Core providers, `pingdotgg/t3code` usage and provider modules, `paradevai/paradev` host-service usage and history routers, Carrier's installed `@anthropic-ai/claude-agent-sdk` (`sdk.d.ts`), Carrier sources ([src/config/providers.ts](../../src/config/providers.ts), [src/harnesses/local.ts](../../src/harnesses/local.ts), [src/chat/schema.ts](../../src/chat/schema.ts), [src/chat/claude.ts](../../src/chat/claude.ts), [src/chat/codex.ts](../../src/chat/codex.ts), [src/storage/executions.ts](../../src/storage/executions.ts), [agent-usage-limit-signals.md](agent-usage-limit-signals.md)), and read-only local checks against `claude` (`2.1.322`), `codex-cli` (`0.167.2`), and `agy` (`1.5.7`).

## Short answer

All three open questions in [usage-and-limits.md](../specs/usage-and-limits.md) are resolved from primary sources and local CLI probes without touching browser cookies. For **Claude live quotas**, calling `usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET({ skipBehaviors: true })` through the Claude Agent SDK (`@anthropic-ai/claude-agent-sdk`, already installed in Carrier, pioneered here by `pingdotgg/t3code`) delegates auth to the `claude` CLI itself, avoids macOS Keychain ACL prompts in unsigned apps, returns in ~4.3s (and fails cleanly with `tokenSource: "none"` when signed out), and delivers `five_hour`, `seven_day`, `model_scoped` windows, `seven_day_breakdown`, and structured `extra_usage` / `spend` money fields (`amount_minor`, `currency`, `exponent: 2`) without direct Keychain reads. For **Codex live quotas**, both `codex app-server` `account/rateLimits/read` (JSON-RPC) and direct `https://chatgpt.com/backend-api/wham/usage` using `$CODEX_HOME/auth.json` return primary/secondary windows, `planType`, and `credits` without cookies (`account/rateLimits/read` also includes `rateLimitResetCredits`). For **Antigravity (`agy`)**, both `agy -p "/usage" --output-format json` (~5s, zero tokens) and Paradev's OAuth call to `daily-cloudcode-pa.googleapis.com/v1internal:retrieveUserQuotaSummary` return the bucketed `5h`/`weekly` remaining fractions and reset times, and neither exposes a numeric AI credits balance; more importantly, **both Paradev and T3 Code read external `agy` history locally** (`transcript_full.jsonl` in Paradev, and read-only SQLite + protobuf decoding of `~/.gemini/antigravity-cli/conversations/*.db` in T3 Code), removing the assumption that `agy` history cannot be scanned on disk.

## Claude live quotas: Agent SDK control probe vs. Keychain OAuth

`steipete/CodexBar` (`docs/claude.md`, `docs/keychain-prompts.md`, `ClaudeOAuthUsageFetcher.swift`) and `paradevai/paradev` (`packages/host-service/src/trpc/router/usage/claude.ts`, `profiles.ts`) both read Claude Code's OAuth token either from `.credentials.json` or via `/usr/bin/security find-generic-password` for service `Claude Code-credentials` (or `Claude Code-credentials-<sha256(configDir)[0..8]>` for non-default `CLAUDE_CONFIG_DIR`) and call `GET https://api.anthropic.com/api/oauth/usage` with header `anthropic-beta: oauth-2025-04-20`. On macOS, `claude` (`2.1.322`) does not write `~/.claude/.credentials.json` when using the OS keychain, and `CodexBar`'s `docs/keychain-prompts.md` documents recurring interactive Keychain ACL dialogs whenever a separate macOS binary — especially an unsigned one like Carrier ([0017](../adr/0017-carrier-is-installed-with-a-homebrew-tap-and-the-app-is-not-signed-with-a-developer-id.md)) — reads foreign Keychain items owned by Claude Code. Furthermore, Paradev's `claude.ts` warns never to run an OAuth refresh outside Claude Code itself (`token_stale` / `token_expired`), because Anthropic's refresh rotation can log out the active CLI session.

`pingdotgg/t3code` (`apps/server/src/provider/ClaudeProvider.ts`, `claudeUsageLimits.ts`) takes a much cleaner native path using `@anthropic-ai/claude-agent-sdk` (already a dependency in Carrier). Passing an empty never-yielding async generator prompt with `persistSession: false`, `disableAllHooks: true`, `mcpServers: {}`, and `strictMcpConfig: true`, awaiting `q.initializationResult()`, and calling `q.usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET({ skipBehaviors: true })` (then aborting/closing the query) asks the user's `claude` binary directly for its rate limits over stdio JSON-RPC. Testing this script directly on this Mac against Carrier's installed SDK (`claude 2.1.322`) took `4314 ms` total (`4042 ms` init + `272 ms` `get_usage`) with **zero Keychain prompts**, returned `account` metadata (`subscriptionType`, `apiProvider`), `five_hour` and `seven_day` windows (`utilization` 0–100 and `resets_at` ISO), `model_scoped` limits (`display_name`, `utilization`, `resets_at`), `seven_day_breakdown` (`rows` by surface such as `claude_code`, `chat`, `cowork`, `other`), and **both** `extra_usage` (`is_enabled`, `monthly_limit`, `used_credits`, `utilization`, `currency`, `decimal_places: 2`, `disabled_reason`) and `spend` (`used: { amount_minor, currency, exponent }`, `limit: { amount_minor, currency, exponent }`, `balance`, `enabled`, `disabled_reason`). Running the same probe against an empty temporary `CLAUDE_CONFIG_DIR` completed cleanly with `account.tokenSource: "none"` and `rate_limits_available: false` without hanging or prompting. Because direct `.credentials.json` reads work cleanly on Linux or plaintext installs in milliseconds while `get_usage` invokes `claude` cleanly without Keychain ACL issues on macOS, Carrier can use plaintext `.credentials.json` + `/api/oauth/usage` when present and non-stale, or default directly to the Claude Agent SDK `get_usage` probe per account `CLAUDE_CONFIG_DIR` on macOS (falling back if `spend` / `extra_usage` fields change since the method is marked experimental). Note the money unit lesson verified directly in the SDK response and T3 Code's `claudeUsageLimits.ts`: `extra_usage.monthly_limit` (`8000`) and `used_credits` (`0`) are in **minor units** (`decimal_places: 2`, matching `spend.limit.amount_minor: 8000, exponent: 2` = `$80.00`), explaining CodexBar's earlier 100x scaling bug on `extra_usage`.

## Codex and Antigravity live quotas

For **Codex**, probing the local `codex-cli` (`0.167.2`) `codex app-server` with `initialize` followed by `account/rateLimits/read` returned `{ rateLimits, rateLimitsByLimitId, credits, planType, rateLimitResetCredits }` natively over JSON-RPC using whichever `CODEX_HOME` launches the child process (`src/chat/codex.ts` already speaks this protocol). Both `primary` (`windowDurationMins: 300`, `usedPercent`, `resetsAt` epoch seconds) and `secondary` (`windowDurationMins: 10080`), per-model limits under `rateLimitsByLimitId`, and `credits: { hasCredits, unlimited, balance }` are present alongside `rateLimitResetCredits`. The alternative direct HTTP path used by CodexBar (`CodexOAuthUsageFetcher.swift`) and Paradev (`packages/host-service/src/trpc/router/usage/codex.ts`) reads `$CODEX_HOME/auth.json` (`tokens.access_token`, `tokens.account_id`, plaintext JSON with no Keychain ACL prompt) and calls `GET https://chatgpt.com/backend-api/wham/usage`, returning `email`, `plan_type`, `rate_limit.primary_window`, `rate_limit.secondary_window`, `additional_rate_limits[]`, and `credits.balance`. Note two practical safeguards from `t3code` (`codexUsageLimits.ts`, `UsageLimitSources.ts`): model-specific rate limits (`limitId !== "codex"`) should not overwrite the main `codex` windows, and Codex also streams cached `rate_limits` inside session JSONLs (`event_msg` `token_count`), which can lag behind an explicit `account/rateLimits/read` or `wham/usage` probe right after a window reset.

For **Antigravity (`agy`)**, running `BROWSER=true agy -p "/usage" --output-format json </dev/null` on `agy` (`1.5.7`) returned `command.data.groups` with named pools (`Gemini Models` containing `gemini-weekly` and `gemini-5h`, `Claude and GPT models` containing `3p-weekly` and `3p-5h`, `Gemini 4 Argon` containing `gemini-argon-wtu-weekly`) and per-bucket `remaining_fraction`, `reset_time`, and `description`, and **confirmed it does not include a numeric AI credits balance**. Paradev's `agy-quota.ts` avoids spawning `agy` (~5s) by reading `security find-generic-password -s "gemini" -a "antigravity" -w` (stripping a `go-keyring-base64:` prefix), refreshing via Google's OAuth client (`oauth2.googleapis.com/token`), and POSTing `{}` to `https://daily-cloudcode-pa.googleapis.com/v1internal:retrieveUserQuotaSummary` (fallback `cloudcode-pa.googleapis.com`); however, Paradev's `agy-quota.ts` also sets `creditsBalance: null` because Google's endpoint returns bucket fractions and reset timestamps without numeric credit balances, and touching the Keychain `gemini` item directly from an unsigned binary risks the same macOS ACL prompt concern as Claude's Keychain item. Calling `agy -p "/usage" --output-format json` (~5s, cached ~60s and only when an `agy` account is configured) keeps credential handling completely inside `agy`.

## Historical logs across Claude, Codex, Antigravity, and local models

Inspecting `t3code` (`usageTranscriptReader.ts`, `usageScanCache.ts`, `claudeUsage.ts`, `codexUsage.ts`, `CodexUsageHistory.ts`, `AntigravityUsage.ts`, `antigravityUsageReader.ts`) and `paradev` (`history/parse.ts`, `history/entries.ts`, `history/agy.ts`, `history/aggregate.ts`, `history/pricing.ts`, `history/model-provider.ts`), plus verifying the files on this Mac, resolves exact schemas and shows one major surprise for `agy`.

On **Claude Code (`$CLAUDE_CONFIG_DIR/projects/**/*.jsonl`)**, each assistant streaming write produces a JSONL row with `type: "assistant"`, `timestamp`, `requestId`, and `message: { id, model, usage }`. Skipping `model === "<synthetic>"`, deduplicating globally across files (because fork/resume/compaction re-emit historical turns) by `(message.id, requestId)` resolves streaming partial snapshots cleanly: Paradev keeps the **last** occurrence seen for each key (since later lines carry final output token totals) while T3 Code merges each channel using `Math.max` and also inspects `usage.iterations` for `advisor_message` sub-calls. In Claude payloads, `input_tokens` **excludes** `cache_read_input_tokens` and `cache_creation_input_tokens`, and `cache_creation` optionally splits 5-minute (`ephemeral_5m_input_tokens`) and 1-hour (`ephemeral_1h_input_tokens`) cache write tiers.

On **Codex (`$CODEX_HOME/sessions/**/*.jsonl`)**, lines with `type: "turn_context"` (or `session_meta`) establish the active `model` and `cwd`, while `type: "event_msg"` lines with `payload.type === "token_count"` carry `info.last_token_usage` (per-step increment) and `info.total_token_usage` (cumulative session counter) plus `rate_limits`. Verified on this Mac and noted in both Paradev (`entries.ts`) and T3 Code (`codexUsage.ts`): Codex emits duplicate `token_count` events with unchanged cumulative totals, so readers must deduplicate identical consecutive snapshots (or track the delta of `total_token_usage` and fall back to `last_token_usage` when `total_token_usage` resets backwards), and critically **`input_tokens` in Codex includes `cached_input_tokens`**, so uncached input tokens equal `max(0, input_tokens - cached_input_tokens)`, while `reasoning_output_tokens` is already included inside `output_tokens`.

On **Antigravity (`agy`) external history**, local inspection corrected an earlier assumption: `~/.gemini/antigravity-cli/conversations/` has 240+ active `.db` SQLite databases (whereas only 6 legacy files are flat `.pb`), plus 214 `~/.gemini/antigravity-cli/brain/<sessionId>/.system_generated/logs/transcript_full.jsonl` logs. `Paradev` (`history/agy.ts`) reads `transcript_full.jsonl` (which gives `input_tokens`, `cache_read_tokens`, `output_tokens`, `created_at` per step, but omits `model`), whereas `t3code` (`Drivers/antigravityUsageReader.ts`) opens `~/.gemini/antigravity-cli/conversations/**/*.db` read-only (`PRAGMA busy_timeout = 100`, querying `gen_metadata`, `steps`, and `trajectory_metadata_blob`), decodes the protobuf blobs with a ~45-line varint/length reader, resolves `modelId` (`MODEL_IDS` map + learned model names from `steps`/`gen_metadata`), reconciles step + retry + generation duplicates via union-find across protobuf usage IDs (`field 11, 12, 7`), and fingerprints `${fileStat}/${walStat}` for incremental caching. Checking `conversation_summaries.db` locally confirmed it stores FTS/session metadata only and zero token counts, making T3 Code's read-only `.db` reader the only local `agy` source that preserves exact models alongside tokens.

For **incremental performance**, T3 Code (`usageTranscriptReader.ts`, `usageScanCache.ts`) caches parsed byte offsets per canonical (`realpath`) file path, verifies the file was appended (not rewritten) via a 64-byte FNV-1a guard hash right before `resumeOffset`, ignores unterminated tail lines during active writes, and skips reading lines exceeding a safety cap (Paradev caps at 32 MiB) so multi-hundred-MB directories stay fast on repeat views.

For **Carrier-originated runs vs. local (`lmstudio` / `ollama`) and deduplication against JSONLs**: [src/chat/claude.ts](../../src/chat/claude.ts) and [src/chat/codex.ts](../../src/chat/codex.ts) already store the CLI conversation UUID (`sessions.nativeId` in `chat.db`), and [src/storage/executions.ts](../../src/storage/executions.ts) records `executions.sessionId` plus `executions.provider` (`lmstudio` | `ollama`) and `executions.model`. When Claude or Codex runs against a local provider ([src/harnesses/local.ts](../../src/harnesses/local.ts)), the account itself declares `provider: "lmstudio" | "ollama"` in `providers.json` ([src/config/providers.ts](../../src/config/providers.ts)). Joining scanned JSONL `sessionId` against `sessions.nativeId` and `executions.sessionId` prevents double-counting turns across DBs and disk logs while reliably tagging which sessions came from Carrier epics vs. Carrier chats vs. external CLI/IDE work and which sessions used a local provider (`$0` cost even if Claude/Codex wrote the JSONL). Any remaining model ID that neither matches a known local runtime nor appears in the bundled LiteLLM-style pricing catalog (`pricing.ts` / `usagePricing.ts`) must never drop totals or guess a cloud rate cleanly: T3 Code (`usagePricing.ts`) marks unpriced rows explicitly (`unpriced` badge / `approximate: true`) and lets the user override or map aliases to `$0` or a custom price.

## UI patterns across the three reference apps

Across `CodexBar`, `Paradev` (`apps/docs/content/docs/usage.mdx`), and `T3 Code` (`docs/user/usage.md`), the UI splits cleanly into two bands rather than mixing percentages and dollars into one number. **Top / Live quotas**: both Paradev and T3 Code render per-account or pooled quota cards showing account label/email/plan badge, `Session (5h)` and `Weekly` progress bars with color thresholds, exact reset countdown/timestamps (`Resets in 2h 14m`), per-model scoped buckets where applicable (such as Claude `Opus`/`Sonnet` or `agy`'s `Gemini` vs. `Claude/GPT` vs. `Argon` pools), extra spend/credits where available (and `N/A` for local runtimes), and multi-account sign-in status or action buttons right on expired accounts. T3 Code also sorts pooled accounts by earliest reset when pooling limits. **Bottom / Historical consumption**: Paradev puts a `Cost ($) / Tokens` metric toggle above a daily stacked bar chart (`7d` / `30d` / `90d` presets), horizontal provider filter pills, and sortable `Models` and `Workspaces` breakdowns (keeping "Cost to you" explicitly separate from "API-equivalent reference"), while T3 Code pairs Breakdown filtering (by provider, model, environment/source) with inline unpriced-model badges and custom price/alias mapping controls. For Carrier's native macOS sidebar (`Usage` section, obeying [macos-ui](../macos-ui.md)), pairing top live quota cards per configured `providers.json` account (Cloud + Local badge) with bottom filterable historical charts and tables (Provider/Account, Model, Cloud vs. Local, Source: Carrier epics / Carrier chat / External) matches all three reference tools while staying idiomatic in SwiftUI.
