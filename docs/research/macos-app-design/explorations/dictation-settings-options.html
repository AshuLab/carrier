Settings — Dictation page

One question: how do we lay out the page so the recognizer, the speech model and the language are understood without friction? Three ways to organize the same data. Everything is clickable: filter, Use, Download (simulated), Delete, language. The state is shared, so what you change in one option shows in the others.

A — One list, filter by recognizer

What you asked for: the whole list, with chips to filter by recognizer. Choosing a model chooses its recognizer; the recognizer is a label on the row, not a step. Active model and language sit on top.

B — Recognizer first, then its models

Three numbered steps: pick the recognizer, pick one of its models, pick the language. Mirrors how the code is built and explains each recognizer in a line. The cost: the full list is never on screen at once.

C — Summary card + comparison table

A card says what dictation uses right now and lets you change the language there. Below, a table to compare every model by size, languages, partial text and licence. Best for choosing between models; the densest.
