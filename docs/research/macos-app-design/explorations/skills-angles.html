Skills: four other angles

B + F worked, but it treats this like a settings form. These four change the idea, not the layout. Each has a few frames: use the small bar above each window. G shows almost nothing until you ask. H shows the real prompt and lets you add to it, no files. I writes the skill for you from a description. J earns trust in a custom skill from what actually happened when it ran. They combine; the notes at the bottom say how.
Everything here is a draft of the Skills tab in Settings.
What it fixesWhat it costs
G · Calm by defaultMost people stay on solve; the tab stops asking them to decide.Almost nothing: a screen state.
H · Show the promptThe small customizations (“use pnpm”, “run this checklist”) need no skill file at all. Transparency: you see what the agent is told.A new optional field per stage (instructions) that build-prompt.ts appends. It is not a skill: it is text that works with any skill.
I · Write with wordsRemoves the hardest step: authoring a skill.One agent run per draft, and the user must read the diff: it can still be wrong.
J · Track record“Carrier can't tell what my skill does” becomes “here is what happened the times it ran”.Small: the engine already knows if a result imported, if the PR stayed open and if anything merged. Needs run history per skill.
