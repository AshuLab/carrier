# Config

**Carrier folder** - The one folder where Carrier keeps everything it owns: `~/.carrier/` by default, changed with `CARRIER_HOME`. Its top holds the files a person edits (`engine.json`, `chat.json`, `providers.json`, `projects.json`), next to one subfolder per process, split by lifecycle: `engine/` (with its `state/`, `logs/`, `repos/`, `worktrees/` and `reviews/`), `chat/` (with its `state/`, `logs/`, `projects/`, `worktrees/`, `pending/` and `sessions/`) and `app/` (the Mac app's, with `state/`, `logs/` and `cache/`, where the speech models a person downloads live). Solve never receives it ([0016](../adr/0016-carrier-keeps-everything-in-one-folder-with-a-subfolder-per-process.md), [0034](../adr/0034-the-carrier-folder-keeps-edited-files-at-the-top-and-splits-each-process-folder-by-lifecycle.md)). It is independent of where the app's code lives or from where it is started.
_Avoid_: shared root, root, Carrier home (that is the app's page of the Carrier world), data folder, workspace (it is an epic's checkout, inside `engine/worktrees/`).

**Config level** - One of the four places a setting lives, by who reads it: the engine's `engine.json`, the chat's `chat.json`, the app's preferences (user defaults, read only by the app) and `providers.json`, the accounts that the engine and the chat host both read ([0020](../adr/0020-accounts-live-in-a-file-both-processes-read.md)). A setting lives in one level and no process reads another's, except the accounts. The chat host starts with neither `chat.json` nor `providers.json`; the engine needs its own `engine.json`.
_Avoid_: settings file (there are two files and the preferences), global config.

**Health check** - The app's answer to "is everything Carrier needs ready?", in the Health tab of Settings, in three layers: this Mac (`git`, `gh` and the logins of `claude`, `codex` and `gh`), Carrier itself (the `carrier` command, the chat host, the engine) and the engine's setup (the checks of `carrier doctor`, once there is a config). Each check is ready, missing, signed out or unknown, and what a failure breaks is switched off with its reason.
_Avoid_: doctor (that is the command that validates an engine's config and is one layer of the health check), diagnostics, setup (that is the wizard that creates the config).

**Config owner** - The process that reads a config file at the top of the Carrier folder and applies a change to it at once: the engine for `engine.json`, the chat host for `chat.json`, `projects.json` and `providers.json`. A front-end sends it the change; when it is not running, `carrier config` writes it with the same Node code ([0053](../adr/0053-a-carrier-config-file-has-one-owner-process-and-a-front-end-writes-it-through-that-process.md)).
_Avoid_: writer, config service.
