Notifications tab: how it works today and options

Where it is stored, and does it work

WhatWhereState
Needs youThe app's user defaults, key notify.needsYou. On when the key is not there.Works: it is checked on every snapshot, so the switch applies at once.
Ready for testUser defaults, notify.readyForTest. On when unset.Works, same way.
PermissionmacOS (System Settings › Notifications › Carrier). The app only reads it; it cannot turn it on.In your screenshot it is Denied: nothing will show until you allow it there. “Send a test” asks again after you do.
Not in the engineThese are preferences of the app, not of config.json. The engine knows nothing about notifications.As designed.

What is missing

Clicking a notification does nothingIt should open the window on that epic. The notification centre's delegate only decides to show the banner; it does not handle the click.
Sound is always onHardcoded to the default sound. No switch.
It shows even when you are looking at the windowThe banner is forced while the app is frontmost. No “only when I am elsewhere”.
Problems are not notifiedGitHub refusing a profile, or Carrier stopping, only turn the menu bar dot on. By design so far; could be a third switch.
Epics that needed you while the app was closedNot notified when it opens: the first snapshot only seeds. It shows them in the window.
“Send a test” gives no feedbackIf the permission is denied, nothing visible happens.

Options for the tab

The state bar changes the system permission; the three layouts react to it. New items are marked new. Switches and buttons work.
System permission
  • What I would pick: A for the structure (the permission is a banner only when it needs your attention, otherwise it takes no room; every event shows what its notification looks like and can send itself as an example) plus from C the new “How” switches (sound, only when I am elsewhere). The notification click that opens the epic is not a setting: I would just build it.
  • Per-event sound (B) is more control than this app needs; two events and one global sound switch is enough.
  • A “problem” switch is the only new event worth discussing: it would notify when GitHub refuses a repo or the engine stops. Off by default, because a flapping network would nag.
