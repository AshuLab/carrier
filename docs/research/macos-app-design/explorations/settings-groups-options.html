Settings — App, Carrier, Chat

Providers holds only the tools and their accounts. Carrier and Chat each decide which providers they use and how each starts, in their own Agents page.

Where each thing goes

App

  • General, Notifications, Appearance, Sidebar, Chat, Keybindings
  • Health: git, gh, carrier and node paths

Providers master-detail

  • Claude Code, Codex, Antigravity: status, version, accounts and their runtime (shared by Carrier and Chat)
  • Local servers (LM Studio, Ollama): status, models
  • No switches, no defaults

Carrier engine only

  • Repos: status, checks and the roles of each repo
  • Agents: the three roles, each with identity, provider, model, effort and what to do when it runs out of tokens
  • Behavior
  • Engine: start with the app, confirm stopping, which carrier and node, the GitHub identity, files and logs

Chat

  • Sessions
  • Agents: which account, model, reasoning, permission
  • Projects
Open:
  1. Repos: a repo's page has Status, Ready for Carrier and Who works here. Decided: four checks. Three already exist in carrier doctor (Carrier can read it, author and reviewer can sign for that owner); Solve is set up (the solve:epic and solve:epic:ready labels; the file docs/agents/solve.md is not checked) is a new read of GitHub. Branch protection is out: it needs admin rights the orchestrator's token probably lacks, so it would say no when it could not look. A role you change opens the same form as Roles (identity, account, model, persona) inside the card, with Reset. No pause per repo. A failed "can sign here" check offers Use another identity (opens that role's form) and Open Identities (install or create the bot there; Create a bot belongs to the Identities page). Defaults: every repo inherits the global roles, which are the Roles page, so a new repo needs nothing; each role row here shows the inherited value and "Open Roles". Try "Add a repo from GitHub".
  2. Agents is three fixed roles: Author, Reviewer and Lead reviewer (optional). No more can be made. Each has Identity (an Agent Forge bot or your gh login, with Create a bot… next to it), Provider, Model, Effort, an optional Persona and, for when it runs out of tokens, a first and a second provider and model. Permissions are not a setting: runs are unattended and always automatic.
  3. New in the engine: effort per role (Claude and Antigravity take --effort; Codex takes model_reasoning_effort through -c), and a model on each failover step (today a failover step names only a provider, and its model comes from the account's default or the harness's). Both also apply to a repo's override.
  4. Hidden, not removed: the mode separate or shared (derived: the same identity on two roles means shared, and the page says the signature will show it), who moves the epic labels (the implementer's identity unless the file says otherwise), the failover triggers (all three) and enabled of the accounts (a key edited by hand; the per-epic choice of provider keeps working as today).
  5. Decided: accounts and their runtime are shared by Carrier and Chat (Display name, Binary path, config dir, Auto-compact, Compact idle threads (Claude only), Launch arguments). They live in a new optional <Carrier folder>/providers.json (no file = one account per provider, this Mac's login), read by the engine and the chat host, edited by the app. config.json loses providers (roles keep naming the account), chat.json loses harness and command and its agents get an account. ADR 0016 needs to say this is the one shared level.
  6. Decided: no Shadow home. A separate CODEX_HOME per account already separates the login.
  7. Launch arguments are stored as a list. Carrier refuses the flags it sets itself (--model, --permission-mode, --output-format, --resume; for Codex the sandbox mode and the run marker), because repeating them would change the permission mode or break the event parsing. The chat of Claude passes them through the SDK's extraArgs; the chat of Codex needs its adapter to accept them (today it starts app-server alone).
  8. Sign in and state use the account's own environment: the status check and the Terminal command carry its CLAUDE_CONFIG_DIR or CODEX_HOME, or claude-work would sign in to the wrong account.
  9. Detecting providers: one detector (binary on the PATH, signed in or not) used by carrier init and by the app, through the chat host. No providers.json yet: it is created with one account per provider found. Later, a provider found but not added shows an "Add" row (try Antigravity); nothing is added or re-added silently. It must use the login shell's PATH (or the one set in Health), because an app opened from Finder does not see Homebrew. Extra accounts, like claude-work, are always added by hand.
  10. No API key or sign-in method: Carrier keeps no secrets. Signing in is the CLI's job; the app shows the state and opens Terminal.
  11. Accounts are added in Providers and each says which role or repo uses it. A role picks one in Agents; a repo can override it in Repos. Identities are GitHub bots, not AI accounts. Try "Add account".
  12. Chat › Agents can have more than one entry per provider (another model, another binary), like chat.json does today.
  13. Lead reviewer: the toggle in the list turns its form on and off (click it).
